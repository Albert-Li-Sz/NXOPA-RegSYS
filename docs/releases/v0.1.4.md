# V0.1.4 · 自配反向代理与镜像拉取修复

发布版本：`v0.1.4`。

## 安装变更

- 新安装默认不拉取、不启动 Caddy，也不占用 80 / 443。向导填写浏览器访问地址、前端和 API 的本机上游端口；默认分别为 `127.0.0.1:8081`、`127.0.0.1:3000`。
- 用户自己的反向代理将 `/api/` 转发到 API，其余请求转发到前端，保留 API 路径、Host / Origin 和原始协议。安装包附 `nginx.conf.example`，域名与 HTTPS 证书由用户配置。
- 已有 Caddy 配置升级时继续保留原入口。准备好自己的代理后，在原 `.env` 增加 `REVERSE_PROXY_MODE=external`、`WEB_PORT`、`API_PORT`，再运行 `bash install.sh up` 切换；原数据库、报名、附件、会话和密钥保留。
- 默认卸载保留数据；明确选择永久卸载后，也会清理当前项目停用的旧证书卷。配置与加密备份继续保留。

## 镜像错误修复

报错中的 `sha256:f9989be93aaf18e0f2ee8da9e8cbaedc1979c5c1aa89e1c8a0dc18524e5eb7f9` 属于官方 `postgres:17.6-alpine` 多架构索引中的证明元数据配置，不属于 Caddy。Docker Hub 源站目前可以读取该文件；不完整的镜像代理可能缺少它。

安装脚本按 Docker 服务端架构选择官方 PostgreSQL 对应的运行镜像摘要，避免拉取该额外文件；仍使用 PostgreSQL 17.6、相同的数据目录与数据卷。安装材料必须包含 `lib.sh` 和两个 `compose.amd64.yaml` / `compose.arm64.yaml` 覆盖文件。镜像顺序拉取，失败时保留具体镜像提示。

增加使用真实官方清单的镜像代理回归测试，模拟上述文件返回 404，验证两个架构的运行摘要都可绕开缺失文件。发布镜像核验检查全部配置文件、证明元数据和镜像层的可用性。

## 安装与更新

下载 `nxopa-regsys-v0.1.4-install.tar.gz` 与 `SHA256SUMS`，核验后解压，在 `install` 目录运行：

```bash
bash install.sh
```

已有实例先取得完整新版安装材料，保留原 `.env`、项目名、数据库密码和加密密钥，再执行 `bash update.sh`，目标镜像版本选择 `v0.1.4`。安装器的健康检查通过后，仍须通过自己的代理检查 `/api/v1/health` 和实际登录。

API、Worker、前端及 LaTeX 发布镜像支持 `linux/amd64` / `linux/arm64`。发布流程在两个原生架构完成空库安装、浏览器登录、中文 PDF、备份恢复、旧版本升级、交互卸载以及 Caddy 到自配代理切换，全部通过后才上传安装附件。附件提供各项结构化验收记录；教程网页、PDF 和源码同步更新。
