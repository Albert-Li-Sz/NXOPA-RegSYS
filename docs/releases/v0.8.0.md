# v0.8.0

修复 2026-10-22 全项目审计中的账号、财务、授权、资源生命周期、部署和前端问题。本版包含数据库迁移与安全边界调整，升级前须备份数据库、附件和原 ENCRYPTION_KEY。

- 邮箱变更使用待验证地址；验证完成前保持原邮箱登录和找回。修改邮箱、绑定及解绑 GitHub / 飞书须重新验证密码或原邮箱验证码；完成邮箱变更后撤销其他会话并通知原邮箱。HTTPS 使用 `__Host-` Cookie，拒绝歧义重复 Cookie。
- 到账参考号通过同一个数据库函数规范化，历史回填和新入账使用相同规则；同账户的同内容凭证在上传与确认两处去重。退款按累计金额要求第二复核人，冲正须由原核账人之外的管理员完成，退款拒绝必须说明原因。
- 历史疑似重复到账及缺少来源的在途单据进入对账流程，不自动改写余额或删除账簿。系统管理员可审计登记缺失归属；已冲正的历史重复款不会要求再次冲正唯一有效款项。
- 待接受邀请绑定实际账号，并随邮箱变更、封禁、注销或对应撤权失效。相同范围的有效管理授权不能重复签发，撤销会收回历史重复授权。
- 审计列表和计数按财务、准考证及系统配置权限过滤；VIEW 不包含报名个人资料。API Token 记录签发人和审计，失去有效系统授权后不能继续使用。Webhook 支持列表、轮换、停用、删除与撤销私网审批，活动关闭外部联动后停止出站。
- 排考先鉴权并限制每批 200 份报名；准考证每批 100 份，每活动最多 200 个待处理任务。PDF 独立队列按活动轮转，邮件保留并发；预览替换旧任务并在一小时后清理。过期租约、编译目录、失效 PDF、会话、令牌、Job 和 Outbox 有明确保留策略。
- CSV 与平台导出逐条读取，限制总量和跨实例并发。对象清理只处理带本安装实例归属标记的无引用对象，保留未标记的历史对象与共享存储中的其他文件。
- SMTP 密码复用绑定主机、端口、加密方式及用户名；投递结果未知时停止自动重发并复用 Message-ID。MCP 远程连接要求 HTTPS，并限制响应体大小。运行时 Markdown 依赖升级至 15.0.3。
- 安装下载全程限制 HTTPS，显式内网测试开关才允许 HTTP。安装器版本和发布版本一致性进入打包门禁，完整版本镜像与公开附件禁止覆盖。恢复前确认、验证归档和 S3 对象并建立快照，失败保持业务服务停止；更新失败恢复安装材料。默认 API 不发布宿主端口，旧 external 双上游模式有独立兼容编排。
- 修复附件上传离页保护、401 / 403 状态刷新、HTTP 复制回退、文本附件 MIME 预览、PDF 图像预算、排考行键与导出性能，并提高文字与主题色对比度。OpenAPI 补齐外部参数、响应、Cookie 和不透明令牌说明。

## 升级与核对

在原安装目录执行：

```bash
installer_tmp="$(mktemp)"
curl --proto '=https' --proto-redir '=https' -fsSL https://raw.githubusercontent.com/Albert-Li-Sz/NXOPA-RegSYS/v0.8.0/install.sh -o "$installer_tmp"
NXOPA_ROOT="$PWD" NXOPA_UPDATE_TAG=v0.8.0 bash "$installer_tmp" update --yes
rm -f "$installer_tmp"
```

升级后重新登录；重新签发无签发人信息的历史 API Token，重新批准历史私网 Webhook。未绑定账号的旧角色邀请会撤销，需重新签发。核对历史财务对账标记、实际收款和发票，完成必要的独立复核后再退款。旧凭证缺少可靠附件摘要时退回重传。模板中的活动字段限定为 id、title、location 和 startsAt，其他信息通过报名字段或单位资料提供。

数据库只使用 `prisma migrate deploy`。部分唯一索引、CHECK 与 JSON 引用查询索引由迁移维护，禁止以 `db push` 替换迁移。回退须恢复兼容备份；不要直接用旧镜像读取新数据库。

发布门禁要求同一提交、干净源码的完整业务及浏览器回归、Hydro / DOMjudge 真实导入、五类镜像的 amd64 / arm64 构建与安装验证。具体结果和镜像摘要见随版本发布的报告与清单。操作教程见 [在线配置教程](https://albert-li-sz.github.io/NXOPA-RegSYS/)。
