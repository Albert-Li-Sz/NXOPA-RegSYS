# V0.1.2 验收记录

日期：2026-10-12。本机环境为 macOS / Apple Silicon、Node.js 24.18.0、pnpm 11.25.0 和 Docker Desktop；数据库、Redis、邮件与评测平台使用独立本地测试实例。

## 修复与回归

`pnpm test:bugs` 在修复前可复现全部 5 个问题，修复后全部通过：

| 用例                   | 验证结果                                                          |
| ---------------------- | ----------------------------------------------------------------- |
| 原邮箱验证链接         | 改邮箱后旧链接返回 400，新链接可验证当前邮箱                      |
| 原邮箱重置链接         | 旧链接返回 400，新链接可重置密码并撤销会话                        |

同一用户的邮件链接签发、消费与邮箱修改通过 PostgreSQL 事务锁串行处理。迁移 `202610120009_invalidate_legacy_email_tokens` 撤销旧版本遗留的未使用邮件链接，避免升级前已经修改邮箱的账号继续受旧链接影响。

## 发布镜像验收

[发布流水线](https://github.com/Albert-Li-Sz/NXOPA-RegSYS/actions/workflows/release.yml) 将 BUG 回归作为构建前置检查，并分别在原生 amd64 / arm64 环境拉取版本镜像完成上述 15 项安装与升级检查。附件生成依赖两个架构验收成功，`installation-amd64.json` 与 `installation-arm64.json` 记录实际结果。

`scripts/verify-published-images.mjs` 使用匿名、只读 registry token 核对四个公开镜像的双架构 manifest、内容摘要、源码提交和版本标签，并检查 `v0.1` / `latest` 与版本镜像一致。附件由白名单打包，包含 `images.json` 和 `SHA256SUMS`。

上述邮件和评测平台检查针对本地真实服务。具体生产域名的证书签发、公众网络访问和自有 SMTP 送达需在部署环境验证。取消报名会撤销本地评测账号映射资格；当前适配器未承诺自动禁用已有远端账号。
