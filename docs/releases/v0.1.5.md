# V0.1.5 · 内部 Caddy 8080 统一入口

新安装由官方 Caddy 在 `127.0.0.1:8080` 提供 HTTP，内部将 `/api/` 转发到 API，其余请求转发到前端。用户自己的 Nginx / OpenResty 将整个站点代理到这个地址并负责公网域名、HTTPS 和证书。内部 Caddy 不占用公网 80 / 443，不申请证书；数据库 5432 仅保留在容器网络中。

- 安装向导默认 `REVERSE_PROXY_MODE=gateway`，只询问一个本机 HTTP 端口。更改端口后，本机访问地址默认值随之更新。
- 两层代理保留路径、查询、正文、Host / Origin、Cookie 和 HTTPS 协议信息，安装包附单上游 `nginx.conf.example`。
- PostgreSQL 17.6 和 Caddy 2.10.2 使用官方对应架构的运行摘要，避免不完整镜像代理要求额外的证明配置；保留现有数据库版本、密钥和卷名。
- v0.1.4 的双上游 `external` 配置与旧公网 `caddy` 配置继续兼容，更新不会自动切换既有入口。备份、恢复和卸载沿用选定的代理模式及架构配置。

## 安装与升级

下载并核验 `nxopa-regsys-v0.1.5-install.tar.gz` 与 `SHA256SUMS`，解压后在 `install` 目录运行 `bash install.sh`。外层代理将整个站点转发到 `http://127.0.0.1:8080`；域名和证书由部署者配置。

已有实例取得新版安装材料并保留原 `.env`、项目名、数据库密码与加密密钥。先备份，再在原配置修改或增加：

```dotenv
REVERSE_PROXY_MODE=gateway
GATEWAY_PORT=127.0.0.1:8080
PUBLIC_URL=https://reg.example.org
```

运行 `bash update.sh`，目标版本选择 `v0.1.5`；外层 Nginx 改为单一上游 8080。旧公网 Caddy 切换时释放原 80 / 443，建议在维护窗口操作。原 `WEB_PORT` / `API_PORT` 或旧 Caddy 入口变量在 gateway 模式下不生效，可保留供回退。完成后检查本机 `/api/v1/health`、公网健康接口和实际登录。
