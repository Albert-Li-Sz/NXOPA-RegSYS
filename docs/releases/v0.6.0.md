# V0.6.0 候选构建

> 该候选在双架构安装任务的前置 CLI 测试中发现发布环境变量污染夹具的问题，未发布正式 Release。修复后由 [V0.6.1](v0.6.1.md) 发布，原标签保留以便追溯。

本版重新组织项目首页与部署说明，将固定版本镜像安装策略完整纳入正式发布。活动、报名、审核及财务功能延续 v0.5.5，本版没有新增数据库迁移。

- README 参考 REA 的阅读布局，增加居中品牌与版本入口、快捷导航、快速开始、报名流程图、功能表、实际界面预览、文档导航和 FAQ。
- 核对部署、开发、账号、线下收费、取消报名、财务保留及权限说明；修复工程结构中过时的 `install` 目录，统一指向 `deploy`，收拢重复维护和验收命令。
- 安装镜像使用完整版本标签，例如 `ghcr.io/albert-li-sz/nxopa-regsys-api:v0.6.0`，不附加 `@sha256`；PostgreSQL、Redis、Caddy 同样使用固定官方版本标签，并保留两个架构的平台选择。
- 安装、更新及备份恢复不再加载旧的自动摘要覆盖。单文件入口兼容旧发布包与已有安装材料，在包校验后转换旧哈希引用，保留版本、平台及实例配置。
- 发布包不再生成 `compose.digest.yaml`；`images.json` 的摘要、来源提交和双架构记录继续用于发布核验，下载文件的 SHA-256 校验继续执行。
- 安装配置拒绝 `latest`、浮动小版本、缺失版本和摘要形式；打包时同步 Compose 的默认标签与发布版本。
- 增加两个架构、三种代理模式及旧包兼容检查，同步配置教程 PDF、源码包和安装文档版本。

## 升级

在实际安装目录执行 `bash install.sh update`，选择 `v0.6.0`。无人值守更新需显式指定目标版本：

```bash
NXOPA_UPDATE_TAG=v0.6.0 bash install.sh update --yes
```

更新先自动加密备份。保留原项目名、数据库密码、`ENCRYPTION_KEY`、附件和升级前备份；本版不改变原有账目、角色或财务处理方式。从更早版本升级仍需遵循[部署文档的迁移与恢复说明](https://github.com/Albert-Li-Sz/NXOPA-RegSYS/blob/v0.6.0/docs/DEPLOYMENT.md#加密备份与恢复)。

## 镜像与验收

镜像：`ghcr.io/albert-li-sz/nxopa-regsys-{api,worker,web,latex,minio}:v0.6.0`，支持 `linux/amd64`、`linux/arm64`。兼容别名 `v0.6`、`latest` 仍在仓库提供，安装器只使用完整版本标签。

发布工作流执行工程与完整业务回归、五类双架构镜像构建，以及两个架构的安装、升级、HTTPS 代理和备份恢复验收。结果随 Release 附件提供；镜像与安装材料核验完成后发布正式 Release。
