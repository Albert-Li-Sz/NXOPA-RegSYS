# v2.2.2

## 修复

- 收款冲正后可以使用原交易参考号更正入账，并重新提交原缴费凭证。历史账簿、原始流水号和凭证保留；未冲正的有效收款仍禁止重复入账，重复执行旧冲正不会释放新收款的占用。
- 统一报名保存、提交和活动配置的活动/排考锁顺序，修复同一活动下不同报名并发保存与提交时的数据库死锁。
- 修复报名者引用本人个人附件并提交后，管理员审核误报“附件不属于此报名”。其他报名不能仅凭附件 ID 越权使用文件。
- 额外到账或冲正多缴部分、不改变参赛资格时，当前有效的待发放和已发放准考证继续可用；退款造成余额不足时仍撤销资格并使准考证失效。
- 拒绝纯空白姓名和必填文本，提交/审核时同步检查历史空白姓名；数字 0 和布尔值 false 仍可作为有效答案。

## 安装与保留数据升级

安装包和五类业务镜像使用固定版本 v2.2.2，支持 linux/amd64 和 linux/arm64。核对同一 Release 的 SHA256SUMS 后解压安装包，运行 `bash install.sh`。

v2.2.1、v2.1.0、v2.0.0 和 v0.10.2 可在原安装目录执行：

```bash
NXOPA_UPDATE_TAG=v2.2.2 bash install.sh update --yes
```

更新先建立加密备份，保留原数据卷、加密密钥、账号、报名、财务、附件及共享比赛凭据，再执行数据库迁移并启动服务。源码部署须先执行 `pnpm db:migrate`，再启动新版 API/Worker。

本版包含两个迁移：历史冲正分录增加冲正标记，交易参考号唯一约束仅针对有效收款；历史上已因版本不符而无法下载的准考证明确标记为 STALE。此类旧证件需管理员重新生成和发放，不自动恢复可能包含过期资料的 PDF。当前版本一致的有效证件保持原状态。

降级须恢复升级前的数据库和文件备份。v0.9.x 和已弃用的 v1.0.0 继续使用独立安装目录和数据卷全新部署。

新增 6 个缺陷回归场景，以及历史冲正、有效收款唯一约束和准考证状态的升级检查。发布流程执行完整业务及浏览器回归、真实 Hydro/DOMjudge 导入与登录，以及双架构全新安装、加密备份恢复和上述四个版本的保留数据升级。验收报告随 Release 附件提供。
