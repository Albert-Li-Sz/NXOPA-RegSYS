# v0.9.2

修复单文件安装和更新后 Caddy 无法读取配置、容器持续 unhealthy 的问题。

- 安装器使用 `umask 077` 解压和复制发布包时，可能生成仅 root 可读的 Caddy 配置。网关以 UID 1000 运行，因此报 `open /etc/caddy/Caddyfile: permission denied`。
- 启动服务前，将当前 Caddy 挂载目录设为 755、Caddyfile 设为 644，覆盖内部网关和原有 Caddy 模式。实例 `.env` 保持 600，原项目、密钥和数据保留。
- 增加单文件安装、已有安装再次启动、跨版本升级的权限回归，验证配置内容和密钥权限保留。

## 升级

在原安装目录执行以下命令，下载新版入口并更新。安装器会先创建加密备份，再更新安装材料、镜像和数据库。

```bash
installer_tmp="$(mktemp)"
curl --proto '=https' --proto-redir '=https' -fsSL https://raw.githubusercontent.com/Albert-Li-Sz/NXOPA-RegSYS/v0.9.2/install.sh -o "$installer_tmp"
NXOPA_ROOT="$PWD" NXOPA_UPDATE_TAG=v0.9.2 bash "$installer_tmp" update --yes
rm -f "$installer_tmp"
```

已经出现权限错误的旧实例，可先修正内部网关权限恢复服务，再执行升级：

```bash
chmod 755 /opt/nxopa-regsys/infra/caddy-gateway && chmod 644 /opt/nxopa-regsys/infra/caddy-gateway/Caddyfile && docker restart nxopa-regsys-caddy-1
```

自定义安装目录或项目名时替换对应路径和容器名。本版沿用 v0.9.1 的 Hydro 学号账号、考场编号及比赛密码规则。升级前保留数据库、附件和原 ENCRYPTION_KEY 的备份。
