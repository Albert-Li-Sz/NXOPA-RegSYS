# V0.2.0 · 一键部署、GitHub 登录与按时间审核

修复反向代理域名与 `PUBLIC_URL` 不一致时登录返回 403“请求来源无效”的问题。`PUBLIC_URL` 只用于生成邮件和邀请链接，允许 HTTP / HTTPS，不再作为来源白名单；TLS、域名及访问控制由反向代理配置，登录后的写操作继续检查 CSRF。内网联动默认 `ALLOW_PRIVATE_INTEGRATIONS=true`，既有显式 false 保留。

## 安装与更新

旧 `install/` 安装目录改为根目录一个 `install.sh` 和 `deploy/` 静态材料。脚本支持交互菜单、安装、更新、卸载、管理员初始化、状态、日志和加密备份恢复；单文件启动自动下载并验证发布包的 SHA-256。

```bash
curl -fsSL https://raw.githubusercontent.com/Albert-Li-Sz/NXOPA-RegSYS/main/install.sh -o install.sh
bash install.sh
```

默认部署到 `/opt/nxopa-regsys`，可以用 `--dir` 指定其他目录。内部官方 Caddy 只在 `127.0.0.1:8080` 提供 HTTP；自有 Nginx / Caddy 将整个站点代理到该入口并配置 HTTPS。PostgreSQL 的 5432 留在容器内部。

在安装根目录执行 `bash install.sh update` 更新，`bash install.sh uninstall` 卸载。更新先加密备份，再同步新版材料与镜像。默认卸载保留数据；永久卸载需要输入项目名确认。旧版本升级使用 `bash install.sh --dir /旧安装根目录`，自动备份并将 `install/.env` 复制到 `deploy/.env`，保留项目名、原密钥、数据库密码及代理模式。

## 账号与审核

- 管理员可以给用户添加标签，在用户和报名列表按标签筛选；统计与 CSV 使用同样的筛选条件。标签检查版本并记录审计。
- 邮箱注册和 GitHub 登录后的参赛账号须完善学号、姓名、班级、学院、性别才可报名；创建和提交都在后端校验，团队已绑定账号的参赛成员也须完善资料。
- 每个竞赛按首次成功提交的先后从 1 编号；草稿没有编号，并发提交不重号，补正、重提与取消保留原编号和首次时间。旧提交自动回填编号；列表、详情和 CSV 展示编号，便于从早到晚审核。
- 支持 GitHub OAuth 登录、当前账号主动绑定与解除绑定。管理员配置 OAuth App 的 Client ID、Client Secret 和 `/api/v1/auth/github/callback` 回调。使用一次性 state、S256 PKCE 和 GitHub 已验证邮箱；同邮箱已有账号不会自动合并，密钥加密保存，GitHub 令牌不持久化。

GitHub 流程参考 [Auth.js GitHub Provider](https://github.com/nextauthjs/next-auth/blob/main/packages/core/src/providers/github.ts) 和 [GitHub 官方 OAuth 文档](https://docs.github.com/en/apps/oauth-apps/building-oauth-apps/authorizing-oauth-apps)。真实 OAuth App 由部署管理员配置；自动化使用独立 GitHub 模拟服务验证授权流程。

## 验证与附件

类型检查、6 项单元测试、19 项安装 CLI 检查、4 项单文件启动 / 迁移 / 更新检查、3 项镜像回归，以及 6 组新版功能与浏览器验收通过。完整源码安装的 15 项检查覆盖生产登录、报名、附件、中文准考证、重启、加密备份恢复和真实 `v0.1.1 → v0.2.0` 数据升级。

发布工作流在原生 amd64 / arm64 上构建并实际安装四个业务镜像，执行交互生命周期、HTTPS 双层代理和旧部署切换验收，核验镜像公开访问与源码标签，成功后才生成 Release 草稿。附件包括安装包、镜像摘要、两种架构的安装 / 交互 / 代理报告、新功能报告、PDF 教程、源码与截图及 Hydro 插件。

升级前保留加密备份与原密钥。旧账号缺失五项资料时需补填，已有报名和历史快照保留；数据库迁移只向前执行，回退需恢复升级前备份。
