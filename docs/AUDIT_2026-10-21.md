## 流程修复

- SYSTEM 权限撤销或卸任时，取消该权限签发的旧邀请，即使仍保留 SENIOR 身份、后来重新授权也不会复活旧邀请。
- 资格失效时为已有远端 ID 登记人工撤权，包括此前已标记 STALE 的映射。重新同步验证成功时只关闭相同远端地址、比赛和账号的旧待办；旧目标待办继续保留。
- 提交使用的个人附件允许相应报名审核人读取，照片可以用于隔离编译准考证。编译重启会清除旧 UID 的辅助文件。
- 上传期间阻止保存、取消及退出登录，避免上传结果写入旧草稿。原账号重新登录后保留会话过期前的编辑；不同账号需先放弃旧草稿。
- 全局模板保存不覆盖站点草稿。财务刷新遇到权限拒绝时移除旧资料，网络故障期间阻止旧操作。未提供 secure-context `randomUUID` 的 HTTP 环境可创建考点。
- 文本字段长度配置拒绝负数、小数和反向范围；公示 CSV 与报名 CSV 使用一致的公式前缀防护。
- 发布证据记录测试起止提交和源码状态、准确命令、浏览器通过/失败/跳过/不稳定数量。筛选运行不能用于打包；未知测试名称不能返回成功。
- 修正部署和截图脚本中的本人核账、旧取消回执断言，以及仅检查 PDF 文件头的薄弱验证。PDF 验证实际读取文档文本，包括隔离与真实准考证号码。

## 验证与交付

`pnpm test:whole-audit` 包含 13 项专项业务回归，`whole-project-audit.spec.ts` 覆盖新增交互路径。完整门禁通过 `pnpm test:full` 在独立 PostgreSQL、Redis、附件目录、邮件和隔离编译容器运行 23 组回归；单元测试验证模板预算、字段范围、平台响应和发布证据拒绝场景。发布继续执行原生 amd64 / arm64 镜像安装、升级、HTTPS 代理、备份和恢复验收，具体结果以本版 Release 的提交及报告为准。

依赖检查：本站应用实际执行链路的依赖当前为 0 条已知告警；外部 Hydro 5.0.7 宿主依赖图有 29 条告警，单独记录于本地 `dependency-runtime-audit.json`。API / Worker 镜像保留了工作区安装形成的依赖仓库，其中包含这些宿主包；本站服务没有加载或启动 Hydro，前端镜像仅包含构建产物，插件压缩包只包含插件源码。这 29 条上游告警未在本版消除，不能把本站运行链路检查结果当成整个镜像或外部 Hydro 服务不存在依赖告警的结论。外部平台的升级和运维需要在其自身环境中验证。

当前 Hydro / DOMjudge 适配器不支持通用自动停用远端账号。本站撤回资格会停止交付并生成待办，管理员仍需在相应远端执行撤权后确认完成。

发布后补充核验：实际匿名拉取 v0.6.7 的 API 镜像，确认依赖仓库内存在 `hydrooj@5.0.7`，据此更正了此前“不打包进本站镜像”的范围表述。该勘误仅修改文档；发布镜像及其通过验收的源码提交仍为 `97bdd2ae44ede61a09045b90bce02970d35293f7`。
