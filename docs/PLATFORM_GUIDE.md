# 平台功能与操作说明

## 安装和更新

根目录 `install.sh` 继续提供安装、更新、卸载、备份和恢复。安装时填写 GitHub 加速前缀，留空直接访问 GitHub；例如填写 `https://gh-proxy.org/`，下载地址会成为 `https://gh-proxy.org/https://github.com/Albert-Li-Sz/NXOPA-RegSYS/releases/download/版本/安装包`。安装包和 SHA256SUMS 都使用相同前缀并校验摘要，配置保存在 `deploy/.env` 的 `NXOPA_GITHUB_PREFIX`。单文件启动可在首次下载前输入，也可传 `--github-prefix`。

新安装可选择内置 MinIO、第三方 S3 或本地存储。默认内置 MinIO，随机生成密钥，API 端点仅在容器网络使用；控制台默认绑定 `127.0.0.1:9001`。同宿主机安装多个实例时为各实例设置不同的 `MINIO_CONSOLE_PORT` 和 Caddy 入口端口。旧环境文件缺少 STORAGE_MODE 时继续使用本地存储，更新不会自动改写既有密钥。

默认官方 Caddy 仍在 `127.0.0.1:8080` 提供统一 HTTP 入口。外部反向代理转发整个站点并负责公网 HTTPS。管理中心“全局设置”的公网地址用于邀请、邮件和文件链接。系统管理员点击“编辑”，在“信任的请求来源”逐行或用逗号填写多个内外网根地址，保存后立即生效；填写协议和端口（如有），不含路径、参数、账号密码或通配符。浏览器写操作还自动允许同源、当前公网地址及环境配置的额外管理来源，已登录请求仍检查 CSRF。HTTPS 入口使用 Secure Cookie；公网 HTTPS 与内网 HTTP 并用时，须将 HTTP 根地址显式加入信任来源，才能在该入口保留登录会话。

MinIO 镜像从[固定官方源码版本](https://github.com/minio/minio/releases/tag/RELEASE.2025-10-15T17-29-55Z)构建，源码及 [Go 工具链](https://go.dev/dl/)均验证 SHA-256；镜像保留上游 AGPL 许可证和源码来源。发布镜像包含 api、worker、web、latex、minio 五个服务，支持 amd64 / arm64。

## 平台文件导出

活动可先开放报名，后期在设置中启用“平台文件导出”。平台导出中心选择活动和平台，导出合格报名的 ZIP。Hydro 使用官方 Onsite Toolkit 的 teams.json；DOMjudge 9.x 依次导入 groups.json、organizations.json、teams.json、accounts.json。包内附账号密码表与操作说明，重复导出账号密码稳定，本站不再连接远端或执行自动同步。参见[完整导入教程](INTEGRATIONS.md)。

可排除非正式报名，也可全部按非正式导入。资格变更、取消或删除报名后，已导入的远端账号由评测管理员手动处理。v0.7.0 为破坏性更新，移除旧服务凭据并取消同步任务，升级前备份。

## 存储和文件

系统管理员进入“管理中心 → 文件存储”配置端点、区域、桶、对象前缀、访问密钥和 Path style。使用 MinIO 通常启用 Path style。AWS S3 可留空自定义端点；第三方桶预先创建时关闭“桶不存在时创建”。密钥留空仅在端点与 Access Key ID 不变时保留，浏览器不会收到已保存的 Secret。

保存后点击“测试当前已保存配置”，实际执行对象写入、读取和删除。配置切换后旧对象继续按原配置读取；“迁移历史文件至当前 S3”会复制附件、头像、准考证和模板预览，验证文件摘要再更新引用，可在任务页查看进度。

竞赛管理“竞赛附件”提供两种用途：公开材料上传后生成链接，复制到 Markdown 比赛简介；私有材料选择队伍后分发。队伍成员在报名详情“队伍附件”下载收到的文件或上传交付文件。成员仅能删除自己的文件，具有文件管理权限的管理员可删除该竞赛文件；已用于财务凭证的文件必须保留。公开文件不开放桶权限，由系统按竞赛公开状态提供访问。

顶部“我的附件”汇总个人上传、报名资料和队伍文件。头像支持 PNG/JPEG、5 MB；普通附件支持 PDF、PNG、JPEG、文本和 ZIP，最多 50 MB。准考证编译仍使用隔离且无网络的 LaTeX Runner，结果存储在 S3，下载时验证资格、发放状态和版本。

加密备份会导出数据库引用的 S3 对象并包含在文件归档中。恢复时将这些对象恢复为本地副本，避免必须连接原 S3 才能查看历史资料；恢复后检查公网地址、SMTP 和 S3 配置，再按需迁移文件。更新和恢复均先保留原加密密钥。

## 邮件

“管理中心 → 邮件设置”支持主 SMTP 和最多十个备用 SMTP。管理员新增备用服务器后，分别填写地址、加密、认证和发件信息，可上移、下移、停用或移除。每封邮件先使用主 SMTP，失败后按照列表顺序尝试已启用的备用；成功即停止，任务结果记录成功服务器及前序失败原因。每次发送重新从主 SMTP 开始。密码加密保存，留空保留同一服务器原密码；更换认证用户名须重新填写。

注册必须先收取并填写邮箱中的六位验证码，验证通过后才创建账号并登录，不会创建未验证的待注册账号。注册验证码十分钟有效，绑定申请邮箱且只能使用一次；重新发送使旧验证码失效。邮箱变更和密码找回仍支持六位验证码及邮件链接，一小时有效；注销验证码十分钟有效。密码重置结束原登录会话。

“管理中心 → 邮件模板”分别配置注册验证、密码重置、注销、报名、开票、工单、实名审核、准考证及通用通知。每类邮件提供对应的默认正文、操作链接和示例数据，仅验证类模板包含验证码；新工单展示工单标题和处理入口。旧版未修改的通用默认格式会自动使用对应业务格式，已自定义的模板保持原样。可编辑完整主题、纯文本和 HTML，支持 `{{siteName}}`、`{{subject}}`、`{{message}}`、`{{actionUrl}}`、`{{code}}`、`{{name}}`、`{{status}}`，HTML 变量自动转义。支持 `{{#code}}…{{/code}}`、`{{#actionUrl}}…{{/actionUrl}}` 条件区块，空值时不显示验证码栏或按钮。编辑不同类型会保留各自草稿，保存只更新当前模板；可撤销当前修改、恢复默认格式，并向当前管理员发送已保存模板的测试邮件。预览与实际投递使用相同渲染逻辑和示例数据，包含完整 HTML 样式。验证类模板必须启用并保留验证码；错误保存会显示原因且保留草稿。

个人中心、报名详情“邮件通知”和工单详情显示收件人、排队、发送、失败与跳过状态。业务邮件失败可由收件人或有对应权限的管理员重发。验证码需要在账号页面重新申请；发送成功表示 SMTP 已接收，最终收件箱投递取决于邮件服务商。

## 用户、实名和管理授权

用户类型只有学生与教师，管理员作为独立授权。学生注册填写学号和入学年份；教师填写工号和入职日期。报名还需完善姓名、班级（学生）、院系和性别。性别仅允许“男”“女”；已有其他值通过实名审核流程更新，不自动改写。

顶部“我的报名”“我的准考证”“我的附件”是同级入口，不再显示返回竞赛或个人中心侧边栏。点击头像菜单中的“个人信息”查看和维护资料，点击左上角 Logo 返回首页。“活动及竞赛中心”保留原竞赛列表功能。首次补全资料后，姓名、学号 / 工号、班级、院系等实名字段固定；总览仍可编辑联系方式、昵称和头像。实名资料在“实名认证”提交，修改需系统管理员或高级管理员审核，通过后更新资料。有授权的用户可在“管理信息”查看竞赛范围、权限项和到期时间，也可卸任；必须保留至少一名永久系统管理员。

| 管理授权   | 权限                                                                                                                           |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 系统管理员 | 全站管理、核心 SMTP / 公网地址 / S3 / GitHub 与 API 配置、授权其他管理员                                                       |
| 高级管理员 | 全站竞赛创建、报名、财务、准考证、文件、工单、学生与教师视图、普通账号资料编辑及封禁、实名审核、授权竞赛管理员；不配置核心信息 |
| 竞赛管理员 | 仅指定竞赛，按查看、竞赛配置、报名审核、财务、准考证、文件、工单、学生与教师视图、平台联动分别授权                             |

“用户中心 → 管理员授权”直接对已有学生或教师授权，选择级别、竞赛、权限与期限；“用户与邀请”仍支持需接收者确认的邀请链接，邀请期限与授权到期时间分别设置。授权到期或撤回后，下一次请求立即失去对应权限。

“用户中心”的学生视图和教师视图提供个人信息、邮箱、入学年份 / 入职日期、参与次数、非正式参与次数、账号状态、注册时间及详情。教师的指导记录也计入参与次数。竞赛管理员只能查看具有学生与教师视图权限的竞赛范围；高级管理员和系统管理员可以查看全站。详情支持资料编辑、封禁和解除封禁；高级管理员不能修改或封禁其他全局管理员。系统管理员可删除其他账号，释放邮箱和用户名、结束所有会话并撤销权限，参赛历史保留。不能封禁自己或停用最后一名永久系统管理员。报名按首次提交时间编号。

管理员顶部入口拆分为“活动及竞赛管理中心”（活动及竞赛管理）、“外接平台中心”（评测平台）、“用户中心”（学生、教师、用户与邀请、管理员授权）、“日志与任务中心”（任务、审计日志）、“审核中心”（实名审核）。核心站点、邮件、存储、GitHub 和 API 设置仍在“管理中心”。各中心按有效授权显示，普通用户不可见；旧 `/admin?tab=…` 链接自动转入对应中心。

设置中可以注销账号，注销结束会话、解除登录绑定并撤回授权。报名、财务与文件记录保留。再次注册同学号 / 工号时须提交实名审核；管理员确认真实身份后才恢复查看历史资料，不自动恢复管理员权限。仅填写同一学号不能获得历史访问权。

## 飞书登录

系统管理员在“管理中心 → 飞书登录”配置 App ID、App Secret 和回调地址。将显示的回调 URL 添加至飞书应用的“开发配置 → 安全设置 → 重定向 URL”，如需邮箱建议开通 `contact:user.email:readonly`。密钥不会返回浏览器，更换 App ID 需要重新填写密钥。

使用飞书官方当前 OAuth v3 令牌接口、state 单次校验和 S256 PKCE，按 App ID 和 open_id 识别账号。首次飞书登录跳转注册页，必须通过本站邮箱验证码后才创建和绑定账号；不按飞书返回的联系邮箱自动合并已有账号。已有账号在个人信息的设置页主动绑定，之后可用飞书登录，也可解除绑定；封禁及注销会阻止登录。

协议参考：[获取授权码](https://open.feishu.cn/document/common-capabilities/sso/api/obtain-oauth-code)、[获取 user_access_token v3](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/authentication-management/access-token/get-user-access-token-v3)、[获取登录用户信息](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/authen-v1/user_info/get)。

## 活动总览

顶部第一个入口“活动总览”为活动数据大屏，可筛选活动、刷新和全屏显示。展示活动总数、报名阶段、累计提交、当前有效报名、参与人次、审核、资格及非正式报名，包含报名规模图和逐活动明细，每 30 秒自动更新。

各列表与表格默认每页 20 项，可选择 20／50／100 项，浏览器分别记住各列表的选择；搜索或更改筛选条件后回到第一页，删除最后一页的最后一项会自动退回有效页。管理活动列表、附件、通知和会话使用后端分页，附件搜索可检索全部有权限的记录。长报名表单、成员资料、字段配置、模板版本及审核历史同样支持分页；翻页保留未保存内容，保存或提交处理整份表单。批量排考及报名勾选跨页保留，筛选范围变化后清除报名列表的勾选。

“活动及竞赛管理中心”列表新增“报名人数”列，分别显示正式与非正式人数。团队按当前有效成员人数统计，不按团队份数统计；草稿、撤回及已删除报名不计入。列表只显示管理员有查看权限的活动。

系统管理员与高级管理员可从活动列表的“删除”或活动详情的“删除活动”永久删除空活动，操作前需确认。任何报名（包括草稿）或独立财务账户都会阻止删除，界面显示具体原因；财务历史不能随活动删除。删除空活动会清理其表单版本、考场、准考证模板及平台关联，撤销对应授权和邀请；原附件转为上传者私有文件并关闭公开链接，独立工单继续保留。已有未保存修改时先选择保留编辑或放弃修改，删除接口再次检查版本及关联记录，避免并发报名被误删。

工具栏、表格操作和弹窗按钮使用统一间距与中心对齐，导入文件控件与普通按钮保持相同高度；窄屏弹窗按钮按单列等宽排列。

删除活动不代替外接平台撤权。系统管理员与高级管理员可在“外接平台中心 → 撤权待办”查看和登记所有活动的人工处理结果，活动删除后此入口仍保留待办；其他活动管理员继续在获授权活动内处理。

累计提交保留已取消的历史提交，当前有效报名与参与人次不计取消的报名；草稿不计入提交统计，归档活动不计入大屏。参与人次按活动累计，同一人参加多场活动会分别计数。普通用户只查看公开活动的汇总，不返回个人资料；全局管理员查看全站，竞赛管理员还能查看获授权的未公开活动。

各下拉选择框支持输入后筛选，只能选择已有选项；用户标签等原本允许新增的字段继续支持新增。

## 队伍公示

竞赛设置启用“队伍公示”并选择公开的审核状态，默认仅公开审核通过的队伍。竞赛卡片提供公示入口，也可以分享 `/contests/竞赛ID/public-teams`，名单无需登录。公示包含队名、英文队名、学校、排名、队员与队长标记、指导老师、审核状态和参赛性质，支持分页和 CSV 导出，不包含邮箱、学号及完整资料答案。排名在报名详情由具有报名管理权限的管理员填写。

## 验收命令

报名流程回归使用 `pnpm test:activity-workflows`，考点选择与分配使用 `pnpm test:exam-sites`，升级和恢复使用 `pnpm test:workflow-upgrade`。`pnpm test:full` 在独立 PostgreSQL、Redis、Mailpit 和 LaTeX 环境中运行 scripts/release-validation.mjs 声明的全部回归套件；其中浏览器覆盖查看／编辑、审核弹窗、考点选择和排考预览。原始结果位于 `.runtime/reports/`，测试数据与正式数据分开。

`pnpm test:platform-features` 在独立 PostgreSQL / Redis / MinIO / Mailpit / LaTeX 环境中运行真实接口、邮件、PDF 和浏览器验收；报告写入 `.runtime/reports/platform-features.json`。`pnpm test:release-features` 保留既有 GitHub OAuth、资料、编号和 UI 回归；`pnpm test:install` 验证实际 Compose 安装、数据卷、PDF 和加密备份恢复。测试使用虚构身份，不复制参考图中的个人资料。

## 报名取消、删除和财务记录

报名创建者确认“永久取消”后，报名、成员和老师关联、邀请、提交与审核快照、准考证及专属资料立即删除；待审核、通过、拒绝和已付款报名采用相同处理。成员与指导老师不能代替创建者取消。具有该活动报名管理权限的管理员可在报名列表“删除”，必须填写原因。删除后可重新报名；旧报名详情与专属附件链接不可访问，座位立即释放。

收款凭证、账簿、退款及发票保存在独立财务账户。创建者进入“我的报名 → 财务记录”，财务管理员进入活动管理的“财务记录”，继续核账、退款和开票；删除不执行自动退款。财务附件继续保留，个人附件、公开材料和独立工单不随报名删除。保留最小删除审计及匿名提交、取消次数，不提供报名恢复功能。

专属对象与编译临时文件通过可重试任务清理。已删除报名不会再生成准考证、发送报名通知或交付外接平台账号。已经创建的远端账号需要管理员在外部平台撤销；“远端撤权待办”保留目标平台、比赛和远端编号，管理员实际完成后再标记完成。本站不会把本地删除标为远端撤销成功。

## 查看、编辑与审核

已保存的个人资料、报名、活动配置、动态字段、邮件模板、SMTP、存储和登录配置默认只读。点击“编辑”开始修改，保存成功返回查看模式；保存失败保留输入，取消恢复原值，离开有未保存内容的页面或切换相关栏目会提示。新建表单直接进入编辑。老师字段与报名其他字段统一保存；邀请、解除关联等操作先保存草稿，避免覆盖输入。

审核意见、开票申请、实名认证及新建／回复工单的草稿也受离开保护。退出登录先处理未保存内容，选择继续编辑不会注销会话。工单附件上传完成后才能提交，提交或上传期间禁止离开；失败时保留输入供重试。开票须核对并勾选确认，修改资料后需重新确认；专票使用单位抬头。

管理员管理他人报名时，进入“编辑报名资料”后使用“保存修改”，没有报名方的提交、撤回提交和财务申请操作。管理员自己创建报名或作为关联老师时保留相应报名方操作。草稿显示草稿，提交后才显示待审核；已完成审核的报名不能撤回为草稿，修改资料后由创建者或关联老师重新提交。

报名列表的“审核”打开独立弹窗，展示报名、成员、老师、动态字段、附件预览、缴费摘要、性质、历史意见和最近两次提交的变化；“修改及查看”进入默认只读的详情。首次审核支持通过、退回补正和拒绝，补正、拒绝必须填写原因。“审核并查看下一条”仅用于首次审核，沿用当前筛选，跨越列表分页。已审核记录显示“修改审核”，打开后需主动选择新的结论并填写原因，再点击“保存审核修改”；已通过记录可退回补正或拒绝。未改动资料的补正记录可修改结论，已改动但未重新提交的资料要等待报名方重新提交。先缴费后审核只限制通过，资料问题可以先退回或拒绝。

财务管理员处理缴费凭证、退款和发票，不代替报名者发起申请；上传实际发票无需额外的报名附件管理权限。已冲正账目显示“已冲正”。活动详情的个人报名、准考证入口只列出本人参与的记录，管理报名使用独立管理入口。比赛账号由主办方导入后分发；只读管理员不能领取他人账号，也不能提前下载未发放的准考证。

收费配置的输入单位为元，支持两位小数，保存时换算为整数分。例如输入 123.45 元后再次编辑仍显示 123.45。核账只确认申报金额是否到账，金额不符应退回凭证重新填写；每份凭证须有银行或支付平台参考号，不能重复使用同一附件入账。申请人、上传者不能审核自己的凭证，超过应收费用的退款需要不同管理员批准和登记完成。

报名管理的“导出名单”按筛选范围导出，每位有效成员一行，每个报名、队伍、成员和老师字段各一列，多名老师依次编号，已删除的历史字段仍可导出。团队的应收及净到账只填在该报名第一行，便于汇总；金额为元。导出需报名管理权限，财务列另需财务权限；单次超过 10000 位成员、500 列或 25 MiB 时需缩小筛选范围。

草稿、待审核、待补正、通过、拒绝与“参加资格已确认”分别展示。仅点击编辑不会撤销审核；资料实际变化后原资格和准考证失效，需要重新提交。后端校验版本、角色、报名和补正期限；并发冲突时须刷新核对，审核意见和表单草稿不会自动清空。

审核保存或重新加载失败后，须成功重新加载报名才能继续提交，已填写的意见和结论保留。连续审核若下一条加载失败，会明确提示本条已保存，可从列表重新加载后继续。更改报名筛选条件即停用旧列表的批量操作；加载成功后根据新范围和有效报名数量恢复按钮，失败时不允许对旧结果继续操作。

## 通用活动与多考场排考

在“活动设置 → 考点选择”点击编辑后，可添加考点名称和详细地址，再保存活动配置。配置考点后，选手报名时必须选择一个开放的考点；个人或整支队伍共用该选择。未配置考点的活动继续按原流程报名。报名管理新增考点列和筛选，统计与名单导出沿用所选考点范围。

考点可停用以停止新选择，已提交的原选择继续保留；草稿在提交前需改选开放考点。已有报名或考场使用的考点不能直接删除。选手更换考点后须重新提交，原座位清空、旧准考证失效。配置多个考点时，考场须关联所属考点，自动、手动或 CSV 排座均在选手所选考点内进行。

创建时可选择“通用活动”或“竞赛”预设，报名形式仍单独选择个人或团队。通用活动默认个人、免费、人工审核、不关联老师，关闭考场、准考证及评测平台；可按需要开启。旧活动保持竞赛预设和原配置。切换已有活动的预设不覆盖原有字段和费用；关闭已启用功能需要明确确认，相关准考证或本地账号交付会失效，原始配置及排考记录继续保留。

启用考场后，在“考场与座位”维护名称、地点、容量、顺序及启用状态。按报名编号、考场顺序自动排考，默认保留已有座位；也可手动安排或下载模板后导入 CSV。所有排考先预览再确认，容量不足、重复占座、跨活动记录或版本冲突时不会部分写入。容量单位为座位，座位号从 1 开始；有座位的考场不能直接删除或停用，可先清空排考。

默认个人一人一座、团队一队一座；团队可选择每位成员一座，同队必须在同一考场。CSV 表头为 `registrationId,personId,room,seat`，按报名排考时 `personId` 留空，`room` 填考场名称；也兼容 `roomId` 表头。优先使用页面下载的模板，避免手填人员编号。

每个活动只有一个排考场次。团队仍共用一张准考证，按成员排考时列出各成员座位。调整座位、考场名称或地点后，受影响准考证失效并需重新生成；未调整的历史准考证继续使用原信息。已存在排考时不能直接更改排考单位，须先清空。

内容未变的考场保存、重复确认相同座位均保留现有准考证。排考预览和保存期间锁定范围及操作按钮；预览失败或版本冲突后旧预览失效，重新预览后才能确认。

## v0.8.0 安全与使用变化

变更邮箱或绑定、解绑第三方登录前，须输入当前密码；没有密码的用户可验证原邮箱验证码。新邮箱验证完成前仍使用原邮箱登录和找回密码。验证完成后，其他设备会话失效，原邮箱收到通知。仅查看活动的 VIEW 授权不包含报名个人资料；业务管理员须取得对应模块权限。

参考号按 Unicode NFKC、空白和大小写规范化，在活动内按交易去重；同一财务账户不能重复使用内容相同的凭证。累计退款超过应收费用时，每笔后续退款须由审批人以外的管理员完成；冲正同样需要原核账人以外的管理员。历史疑似重复到账先对账，不能直接继续退款。拒绝退款须填写原因。

排考每次最多 200 份报名，准考证生成每次最多 100 份，每活动待处理编译任务最多 200 个。预览一小时后失效，Worker 自动清理预览和过期编译目录。
