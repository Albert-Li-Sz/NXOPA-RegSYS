{\Large\color{brand}配置教程}
\vspace{5mm}

本教程从首次部署开始，说明站点与邮件设置、链接授权、评测平台绑定、竞赛规则和准考证模板的配置方法。系统管理员维护全站配置，竞赛管理员仅管理获得授权的竞赛。

\shot[0.38\textheight]{01-home}{独立首页：点击“进入报名系统”后进入登录或竞赛列表。}

\textbf{建议配置顺序}

部署与初始化管理员 → 站点和邮件 → 链接授权 → 评测平台 → 竞赛规则与字段 → 准考证 → 测试与备份。

截图来自本地运行的实际页面。教程中的邮箱、域名、竞赛和账号均为虚构示例；截图未展示密码、插件密钥或原始邀请令牌。示例竞赛未公开发布，教程所用临时邮件设置已恢复。

{\small\color{muted}功能范围：本站邮箱与密码登录、个人 / 团队报名、线下财务、工单、LaTeX 准考证、Hydro / DOMjudge 联动及只读 MCP。第三方登录与账号绑定已取消。}

\section{首次部署与管理员初始化}
\textbf{准备环境。}安装 Docker 和 Docker Compose。在项目目录执行 \code{pnpm setup} 生成初始环境文件与随机加密密钥；使用源码命令时需 Node.js 24.12 以上和项目指定的 pnpm。已有环境文件不会被此命令覆盖。
\begin{Code}
pnpm install --frozen-lockfile
pnpm setup
docker compose up -d --build
docker compose ps
docker compose run --rm api pnpm bootstrap:admin
curl --fail http://localhost:8080/api/v1/health
\end{Code}
初始化命令交互输入邮箱和密码，密码输入不回显。首次管理员由此命令创建；它不会覆盖已有账号。正式部署不使用开发演示账号。健康检查应返回 \code{status: ok}，API、数据库与缓存服务应处于健康状态。

\textbf{设置公网地址。}上线前编辑项目根目录 \code{.env} 中的部署项。下列地址与密码占位值需要替换。邮件链接以部署站点地址为基址，因此应先设定正确域名。
\begin{Code}
DEPLOY_PUBLIC_URL=https://contest.example.org
SITE_ADDRESS=contest.example.org
HTTP_PORT=80
HTTPS_PORT=443
POSTGRES_PASSWORD=replace_with_a_strong_password
ALLOW_PRIVATE_INTEGRATIONS=false
\end{Code}
原生开发使用 \code{PUBLIC_URL}，正式 Compose 使用 \code{DEPLOY_PUBLIC_URL}。如果评测平台确实位于受信任内网，再显式启用内网联动；正式环境外部评测接口要求 HTTPS。

\textbf{需要留在部署环境的配置：}数据库、缓存、私有文件目录、站点公开地址和 \code{ENCRYPTION_KEY}。这些属于运行基础设施。保留同一个加密密钥，否则无法解密已有邮件密码、评测凭据与备份。

\textbf{可在管理中心调整的配置：}站点名称、主色、页脚、邮件服务、用户授权、评测平台、接口令牌、全局字段和准考证模板。首次登录后优先完成邮件配置，以便用户验证邮箱和找回密码。

\section{首页、登录与站点设置}
首页 \code{/} 独立展示系统介绍。未登录时点击“进入报名系统”，会跳转登录；直接访问竞赛列表或竞赛详情也会触发登录检查。登录成功后返回原本准备访问的页面，包括详情页参数。
\shot[0.31\textheight]{02-login}{登录入口：使用本站用户名或邮箱与密码。}

系统管理员登录后打开“管理中心 → 全局设置”，调整站点名称、主色与页脚，并点击“保存”。竞赛管理员没有全局设置权限。默认主色为 \texttt{\#2080F0}。
\shot[0.24\textheight]{04-site}{全局设置中的站点配置。}

公开邮箱注册保留；用户验证邮箱后才可提交报名或确认授权。本站密码与评测平台比赛账号的密码分别管理。首页不会展示已登录用户的管理导航，进入报名系统后再显示相应入口。

\section{邮件服务：保存、检测与实际收件}
打开“管理中心 → 邮件设置”。只有系统管理员可以查看、修改或测试邮件配置。未在后台保存时，使用部署环境中的初始 SMTP 配置；后台保存后优先使用数据库配置，无需重启 API 或后台任务服务。
\shot[0.47\textheight]{03-mail}{本地邮件测试示例：保存配置，检测连接，再向当前管理员发送测试邮件。}

\begin{tabularx}{\linewidth}{@{}lX@{}}\toprule
配置项 & 填写方法\\\midrule
服务器地址 / 端口 & 填服务商的 SMTP 主机名，不含协议与路径；端口按服务商要求填写。\\
连接加密 & 465 通常用“加密连接”；587 通常用“连接后升级加密”。按服务商文档确认。\\
服务器认证 & 通常启用。填写服务商用户名及密码或邮箱授权码。\\
发件邮箱 / 名称 & 使用服务商允许的发件地址；名称建议填写系统名称。\\\bottomrule
\end{tabularx}

先保存，再“检测连接”，最后“发送测试邮件”。测试邮件只发给当前管理员。任务成功后还应检查实际收件箱或垃圾邮件；连接检测通过不能单独证明邮件可送达。加密方式对应关系见\href{https://nodemailer.com/smtp}{官方邮件配置说明}。

密码加密保存且不返回浏览器。编辑时留空保留原密码；更换认证用户名时重新填写密码。关闭服务器认证并保存，会清除认证密码。关闭邮件服务后不能发送验证和找回邮件，失败任务会保留原因供管理员处理。

\newpage
\section{通过链接授予账号身份}
打开“管理中心 → 用户权限”，点击“生成邀请链接”。选择邀请类型、已有账号或受邀邮箱；竞赛管理员还需选择授权竞赛。默认有效期为 7 天，可设置 1 至 30 天。
\shot[0.55\textheight]{05-role-invitation}{生成竞赛管理员授权链接的配置表单。}

\begin{enumerate}
\item 点击“生成链接”并复制 URL，交给指定接收者。链接只在生成时展示。
\item 接收者通过该 URL 登录或注册指定邮箱，完成邮箱验证。
\item 接收者在邀请页面查看身份和竞赛范围，点击“确认接受”后授权才生效。
\end{enumerate}
仅生成或打开链接不会增加权限。账号邀请不附加管理员权限；系统管理员、竞赛管理员、指导老师身份分别邀请。撤销未确认邀请立即使链接失效；撤销已有角色后，旧链接不能重新恢复权限。

\newpage
\section{授权确认与范围检查}
\shot[0.46\textheight]{06-role-confirmation}{接收者确认前查看身份、受邀邮箱、有效期和指定竞赛。}

确认后刷新管理中心，竞赛管理员应只看到获得授权的竞赛，并可处理对应报名、财务、工单和准考证。竞赛管理员不能修改全站 SMTP 设置或评测实例的接入凭据。

指导老师身份也通过邀请确认。老师与某份报名的关联还需通过链接确认，关联解除后立即失去该报名的访问和代办权限。队伍成员邀请保持独立确认流程；竞赛选择“队长代填”时按照竞赛规则录入人员信息。

\textbf{排查常见问题}
\begin{itemize}
\item 邮箱不匹配：使用邀请指定邮箱登录，不能由其他账号接受。
\item 邮箱未验证：到账号中心重新发送验证邮件，再返回邀请页面。
\item 链接过期或撤销：由系统管理员生成新的邀请。
\item 权限范围不符：检查是否选中了正确竞赛，以及身份是否已经被撤销。
\end{itemize}

\section{接入 Hydro 评测平台}
Hydro 接入使用项目提供的桥接插件。当前适配目标版本为 5.0.7。先在项目目录生成插件包：
\begin{Code}
pnpm package:hydro
\end{Code}
生成的 \code{dist} 中包含安装包。在 Hydro 的 Node.js 环境安装该包，把 \code{hydro-contest-center} 加入 \code{~/.hydro/addon.json}。

配置桥接密钥 \code{CONTEST_CENTER_TOKEN}，长度至少 32 字符。允许域列表通过 \code{CONTEST_CENTER_DOMAINS} 设置，然后重启 Hydro。详细路由和安装说明见项目 \code{docs/INTEGRATIONS.md}。

在“管理中心 → 评测平台”添加实例，填写中文名称、Hydro 类型、实例地址与相同的插件密钥，选择允许使用该实例的本站竞赛，并保存。
\shot[0.55\textheight]{07-hydro-instance}{Hydro 实例配置示例；插件密钥未展示。}

凭据加密保存，编辑时留空保留原值。新建实例或切换平台类型时，需要填写对应凭据。实例保存后继续配置比赛绑定，单独添加实例不会创建参赛账号。

\newpage
\section{接入 DOMjudge 评测平台}
当前适配目标版本为 9.0.1。先在 DOMjudge 建立目标比赛，并创建同时具有 \code{api_reader} 与 \code{api_writer} 角色的独立服务账号。

打开“管理中心 → 评测平台”，添加实例，填写中文名称、DOMjudge 类型、实例地址，以及服务账号用户名和密码。选择可使用此实例的本站竞赛，再保存。
\shot[0.58\textheight]{08-domjudge-instance}{DOMjudge 实例配置示例；使用服务账号，密码未展示。}

在比赛绑定中填写目标比赛编号。如果比赛按分组限制参赛，应填写正确分组；当前界面支持一个分组。组织编号可选。新比赛账号创建后会读取远端队伍与用户，确认参赛关联；重复同步复用本站建立的映射。

实例地址、服务账号权限、比赛编号或分组错误，均可能使同步失败。应先修正配置，再在“任务”中重试。探测通过只代表接口可连接，需要另行核验比赛账号实际登录和目标比赛访问。

\section{比赛绑定与报名同步}
在“管理中心 → 评测平台”的“比赛绑定与报名同步”区域选择本站竞赛，再选择已获授权且启用的评测实例，填写目标比赛编号。Hydro 还需填写域编号；DOMjudge 根据远端比赛要求填写组织和分组。
\shot[0.56\textheight]{09-contest-binding}{绑定示例：本站竞赛关联目标比赛，并设置自动同步。}

\begin{itemize}
\item 自动同步：报名资料、人员与老师关联、审核和确认净收款满足要求，参赛资格生效后才派发任务。
\item 手动同步：进入具体报名的“比赛账号”页，使用“同步比赛账号”按钮。
\item 失败重试：查看任务原因，修正配置后重试；重复执行不会重复建立本站已映射的比赛账号。
\end{itemize}
本站账号和 OJ 比赛账号独立管理。资料或净收款变化导致本站资格失效时，停止向用户交付原比赛账号；当前适配器不支持自动停用远端账号，管理员需在评测系统内处理已有账号。

\newpage
\section{竞赛报名规则与线下财务}
打开“管理中心 → 竞赛”，创建或编辑竞赛。设置竞赛名称、赛季、时间、地点、公告和发布状态，再配置报名规则。草稿不显示在公开竞赛列表。
\shot[0.30\textheight]{10-contest-policy}{团队报名示例：邀请成员、人数限制、老师关联与人工审核。}

个人报名固定一人。团队报名设置最少 / 最多人数，以及成员邀请或队长代填。老师可设置为必需、可选或不启用；必需老师的报名需要有效确认关联。
\shot[0.28\textheight]{11-contest-finance}{线下财务示例：按报名单计费，先审核再缴费。}

可设置免费、按报名单或按人数计费；金额单位是分，100 分等于 1 元。填写线下收款说明，选择“先审核，再缴费”或“先缴费，再审核”，并设置退款与开票。参赛者上传凭证后，由管理员确认实际到账；部分到账不会被视为足额缴费。退款完成需要记录实际退款，开票由管理员上传实际发票。

\section{配置报名字段}
在竞赛“报名字段”页增加字段，或从全局字段导入。设置中文名称、稳定键名、作用域、类型、必填与敏感标记，以及选项或条件。提交报名会保存人员、表单与费用快照；关键资料修改需要重新审核。
\shot[0.48\textheight]{12-fields}{可视化字段列表：参赛者、队伍、老师或报名单的字段分别配置。}

\begin{tabularx}{\linewidth}{@{}lX@{}}\toprule
作用域 & 使用场景\\\midrule
参赛者 & 学校、学号、专业、电话等个人资料。\\
队伍 & 队伍标识、队伍附加资料。\\
指导老师 & 老师关联后补充填写的竞赛信息。\\
报名单 & 整份报名需要提交的其他信息。\\\bottomrule
\end{tabularx}

键名用于接口和模板变量，保存后保持稳定。类型使用短文本、长文本、数字、日期、单选、多选、开关、文件或照片。选项字段需要提供选项内容；条件字段只在条件满足时显示。敏感字段在接口查询中需要明确授权。

\newpage
\section{配置准考证模板与发放}

准考证遵循个人报名一人一张、团队报名全队一张。系统管理员在“全局设置”维护全局模板；竞赛管理员在竞赛“准考证模板”页保存竞赛版本、选择字段并预览。
\shot[0.60\textheight]{13-admission-template}{模板源码、保存与预览按钮；右侧字段面板可插入变量。}

竞赛模板优先于全局模板。管理员在报名管理中选取已获资格的报名，配置考点、考场、座位，批量生成并确认发放。用户只可下载已发放且版本有效的文件；资料、资格或模板变化会使旧文件失效。

\section{模板语法、任务与维护}
模板仅使用受限变量、条件与循环。字段数据统一转义，不能直接插入任意原始代码。下面展示团队成员循环；个人字段可使用 \code{participant.name} 与 \code{participant.answers.school}。
\begin{Code}
\documentclass[UTF8,fontset=fandol]{ctexart}
\begin{document}
{{contest.title}} 准考证
编号：{{admission.number}}
考场：{{admission.room}}  座位：{{admission.seat}}
{{#each team.members}}
{{this.name}}：{{this.answers.school}}\\
{{/each}}
\end{document}
\end{Code}
预览无误后保存新版本。生成任务失败时查看编译原因，修复后重新生成；失败文件不会向参赛者发放。完整变量、照片字段和座位导入格式见 \code{docs/ADMISSIONS.md}。
\shot[0.12\textheight]{14-jobs}{任务页：检查后台任务服务、待派发事件和失败任务。}

在“任务”页查看状态、错误和尝试次数，失败任务可重试。邮件测试状态表示服务器已接收邮件，实际送达仍需检查收件箱。接口令牌与签名事件推送在“API 与 Webhook”配置；按竞赛与字段限制权限，只读 MCP 使用专用查询令牌。接口详情见 \code{docs/API.md}。

\begin{Code}
bash scripts/backup.sh /srv/contest-backups
bash scripts/restore.sh /srv/contest-backups/contest-center-YYYYMMDDTHHMMSSZ.ccbak
\end{Code}
升级前备份数据库、私有附件与环境文件；备份包含后台邮件设置。异机恢复使用原加密密钥，并先在隔离环境核验。修改数据库与站点公开地址仍需更新部署环境并重启服务；邮件后台配置无需重启。
