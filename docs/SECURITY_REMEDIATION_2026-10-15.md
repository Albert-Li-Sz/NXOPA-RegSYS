# 安全修复复核与费用／导出验收

审计日期：2026-10-15；修复验收：2026-10-16（Asia/Shanghai）。基于 `8e9fca5`（v0.5.1）后的本地工作区，参考 [原始安全审计](releases/SECURITY_AUDIT_2026-10-15.md)，逐项复核并实现修复。原报告保留原样；其中的建议和代码片段作为待验证材料处理。修复验收阶段未推送、发布镜像或修改正式数据库；后续 v0.5.5 发布检查结果随 Release 附件提供。

## 用户可见变化

- 费用配置以**元**输入，保留两位小数；123.45 元保存为 12345 分，再次编辑仍为 123.45。接口、数据库及旧配置继续采用整数分，避免迁移造成金额变化。
- 报名管理导出 CSV 时，每位有效成员一行，每个成员、队伍、报名和老师字段各一列。多名老师依次编号；历史表单及历史答案仍有独立列。逗号、引号、换行按 CSV 规范保留，公式前缀转义。
- 导出需要报名管理权限；应收与净到账列另需财务权限，单位为元。团队金额仅出现在该报名第一行，避免统计重复。上限为 10000 位成员、500 列、25 MiB，超限整次拒绝，筛选及数量留审计。
- 核账只确认凭证申报金额，金额不符应退回。确认必须记录渠道交易参考号，同一参考号组合不能重复入账；同一附件只能绑定一张凭证。申请人、凭证上传者不能处理自己的核账，超过应收的退款须由不同管理员批准和完成。
- 普通管理员不能替换他人登录邮箱；用户通过本人资料和验证流程变更邮箱。生产环境关闭 Swagger，开发文档及源码 OpenAPI 保留。

## 依赖、迁移与验证

升级 Nodemailer 至 10.1.1 系列，约束 js-yaml 至 5.4.3、deepmerge-ts 至 8.0.2、mysql2 至 3.24.6，并重新生成 Prisma 客户端。应用运行时依赖扫描为 0 条公告；Hydro 插件可选宿主图另有 29 条公告，单独记录，**不代表宿主平台或整个工作区无漏洞**。

新增三个迁移，不自动更改历史余额。升级前备份数据库和文件并保留原 ENCRYPTION_KEY；新建凭证唯一占用从历史凭证中优先选择已确认记录，其余标记对账，不删账。旧版本回退需要恢复兼容备份。

名单导出按 25 份报名分批读取，丢弃不用于导出的提交副本，并对累计扫描资料另设 50 MiB 保护，避免只在最终输出时检查大小。跨两个完整批次、空的末尾批次、团队成员及历史字段均有针对性接口验证。

Webhook 的内网审批也不能放行已知云元数据地址，已根据 [AWS](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/instancedata-data-retrieval.html)、[Google Cloud](https://docs.cloud.google.com/firewall/docs/firewalls) 与 [阿里云](https://help.aliyun.com/zh/eci/user-guide/obtain-the-metadata-from-a-container-2) 文档补充 IPv4／IPv6 及映射地址检查。旧内网 Webhook 不会自动获得审批，升级后由系统管理员明确重新创建并配置接收端签名。

验证命令与结果记录于 [机器可读验收记录](acceptance/security-remediation.json)。针对性安全接口覆盖金额不可篡改、自审、重复凭证／参考号、双人退款、邮箱权限、容量并发、匿名审计、四类字段 CSV、Webhook、Cookie、重置限流、慢平台取消、财务集合与文件参数。另有真实浏览器、SMTP、PDF、独立数据库升级恢复及恶意归档测试。

最终全量回归 20 组及 77 个浏览器场景通过；最后的导出内存保护与元数据拦截变更后，安全接口 20 项、专项导出 2 项、单元 22 项、类型检查及构建再次通过。生产平台 12 项、OAuth 与页面 8 组、恶意归档 18 项、镜像摘要 4 项、安装 CLI 20 项、初始化 5 项、静态服务 1 项通过；格式检查通过。全量与针对性检查的执行顺序及边界均记录在验收 JSON 中。

生产 Web 验收使用本轮静态构建、生产 API、官方 Caddy、S3 与真实浏览器。最初发现 CSP 的 connect-src 未允许临时 Blob，导致 PDF 无法读取；浏览器校验器的可选 JIT 探测也产生策略违规。已允许本地 Blob 读取，并在构建表单 schema 前将浏览器校验切换为无 JIT 模式，继续禁止脚本 unsafe-eval。修复后中文 PDF 实际渲染完成，手机、平板和桌面页面无 CSP 违规。可复现命令为 `PLATFORM_TEST_PRODUCTION_WEB=1 pnpm test:platform-features`，需要先运行 `pnpm build`。

完整源码容器安装尝试在 Docker Hub 基础镜像授权下载阶段超时，未进入新镜像启动及安装入口备份恢复，**不能列为通过**。本轮的原生生产模式、官方 Caddy、独立数据库升级／恢复、归档验证及安装 CLI／镜像摘要测试分别有实际结果；这些检查不替代完整源码镜像安装。正式发布前应在网络可用环境重跑 `INSTALL_TEST_MODE=source pnpm test:install`。

本次测试使用独立数据及本地服务。真实第三方平台的远端撤权仍是显式待办；本地删除不会表示远端已撤权。历史财务重复项和上述供应链／AAD／初始化权限余项已明确列示，未用“全部漏洞清零”替代逐项结论。
